`@lynstack/class-recipe` maps a component's
[variants](/recipe/class-recipe/glossary/#variant), such as its tone and
size, to its class names, for any CSS approach. You write the classes of
each option once, in a [recipe](/recipe/class-recipe/glossary/#recipe),
and call the recipe with the component's props:

## Which function to use

| You want to                                                                | Use                                                     |
| -------------------------------------------------------------------------- | ------------------------------------------------------- |
| Style one element, such as a button                                        | [`cva`](/recipe/class-recipe/cva/)                      |
| Style several elements together, such as a card and its header             | [`sva`](/recipe/class-recipe/sva/)                      |
| Join class names, as with `clsx`                                           | [`cx`](/recipe/class-recipe/cx/)                        |
| Merge classes with a custom join, such as `twMerge`, or turn off the cache | [`createRecipes`](/recipe/class-recipe/create-recipes/) |

## What it gives you

- **Fast.** A recipe compiles its config once and caches the class name of
  each selection, so most calls are a lookup. It runs about {speedup} times as
  many calls per second as `class-variance-authority` (see
  [Benchmarks](/recipe/class-recipe/performance/)).
- **Type-safe.** Variant names, options, and slots are inferred from the
  config. An unknown option or slot is a type error, and a variant without
  a default is required, so a component cannot forget to choose it.
- **Pluggable.** Bring your own join function, such as `twMerge`, to
  resolve conflicting classes. It runs once per selection, not on every
  call.
- **Small.** ES modules only and tree-shakable. Its one dependency is
  [`@lynstack/recipe`](/recipe/recipe/), the engine it is built on, and
  [Bundlephobia](https://bundlephobia.com/package/@lynstack/class-recipe)
  shows its size.

[Why class-recipe](/recipe/class-recipe/why-class-recipe/) compares it
with class-variance-authority and tailwind-variants. The
[glossary](/recipe/class-recipe/glossary/) defines the terms these docs
use.

## When to use it

Use it to style components with class names: Tailwind CSS, CSS Modules, or
any stylesheet. To map variants to values other than class names, such as
style objects, use [`@lynstack/recipe`](/recipe/recipe/), the engine
class-recipe is built on.
