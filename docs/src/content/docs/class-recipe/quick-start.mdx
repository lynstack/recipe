This page styles a button and a card with Tailwind CSS classes. The same
steps apply to any CSS approach. Install the package first (see
[Installation](/recipe/class-recipe/installation/)). The
[glossary](/recipe/class-recipe/glossary/) defines each term.

## 1. Create a recipe

`cva` takes the classes of an element: those it always has, in `base`, and
those of each [option](/recipe/class-recipe/glossary/#option) of each
[variant](/recipe/class-recipe/glossary/#variant), in `variants`. The
recipe below also has a
[compound variant](/recipe/class-recipe/glossary/#compound-variant): classes
that it adds only when several variants have particular options at the
same time. Here, the hover color applies only to a primary button that is
not loading. Create the recipe once, at the top level of a module:

<RecipeExample name="class-recipe/quick-start/button" />

## 2. Call it

A recipe takes a [selection](/recipe/class-recipe/glossary/#selection),
the variants you choose, and returns the class name:

<RecipeExample
  name="class-recipe/quick-start/button"
  source={false}
  calls={[{}, { tone: "neutral", size: "sm" }, { loading: true }]}
/>

- `tone` and `size` have defaults, so a selection may leave them out.
- `loading` declares only `true`, so it is a boolean variant: optional,
  and `false` by default.
- The compound variant adds its classes when `tone` is `primary` and
  `loading` is `false`, which the first call matches through the
  defaults.

## 3. Use it in a component

`VariantsOf` types a component's props from its recipe, and the recipe
takes a `className` that it adds last:

```tsx
import type { ComponentProps } from "react";
import type { VariantsOf } from "@lynstack/class-recipe";

type ButtonProps = ComponentProps<"button"> & VariantsOf<typeof button>;

export function Button({
  tone,
  size,
  loading,
  className,
  ...props
}: ButtonProps) {
  return (
    <button className={button({ tone, size, loading, className })} {...props} />
  );
}
```

See [Building components](/recipe/class-recipe/building-components/) for
passing all props at once with `variantKeys`, and for variant names such
as `size` that HTML elements also use.

## 4. Style several elements with `sva`

A component with several elements, its
[slots](/recipe/class-recipe/glossary/#slot), uses one slot recipe, which
returns the class name of every slot:

<RecipeExample name="class-recipe/quick-start/card" calls={[{ size: "sm" }]} />

See [sva](/recipe/class-recipe/sva/).

## 5. Resolve conflicts, if you need to

Do you need tailwind-merge? No, if your recipes are conflict-free. Yes, if
a `className` that a caller passes must replace the recipe's classes.

With the default join, every class is kept, so a recipe should never set
one CSS property twice (see
[Writing conflict-free recipes](/recipe/class-recipe/conflict-free-recipes/)).
To let classes override each other instead, create the functions with
`twMerge`, once, in a module of your own:

```ts
// src/lib/recipe.ts
import { createRecipes } from "@lynstack/class-recipe";
import { twMerge } from "tailwind-merge";

export const { cx, cva, sva } = createRecipes({ join: twMerge });
```

See [Merging classes](/recipe/class-recipe/tailwind-merge/).
