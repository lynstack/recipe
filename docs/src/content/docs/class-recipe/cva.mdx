`cva` creates a recipe, which returns the class name of one element for a
selection of variants. It is also exported as `createRecipe`. For how
variants work, read [Variants](/recipe/class-recipe/variants/) first.

<RecipePlayground name="class-recipe/cva/badge" />

## Signature

```ts
import { cva } from "@lynstack/class-recipe";

const recipe = cva(config);
recipe(props); // => string
```

`cva` infers the types of the recipe from `config`: the names of the
variants and options, and which variants are required. Its type is
`CreateRecipe` (see [All exports](/recipe/class-recipe/exports/)).

## The config

| Property           | Required | Description                                                                                                                                                             |
| ------------------ | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `variants`         | Required | For each variant name, the classes of each of its options, as a string. Pass `variants: {}` when the recipe has no variants. `className` and `classNames` are reserved. |
| `base`             | Optional | The classes the element always has.                                                                                                                                     |
| `compoundVariants` | Optional | A list of compound variants: classes added when several variants have particular options at the same time.                                                              |
| `defaultVariants`  | Optional | The option each variant uses when a call leaves it out. A variant without a default is required.                                                                        |
| `composes`         | Optional | Recipes whose configs the recipe adds before its own; see [Composing recipes](/recipe/class-recipe/composing/).                                                         |
| `cache`            | Optional | Whether the recipe caches its class names. Defaults to the `cache` option of [`createRecipes`](/recipe/class-recipe/create-recipes/), which is `true`.                  |

`variants` is required even when it is empty. A config without it is a
type error, and throws a `TypeError` ("Cannot convert undefined or null to
object") when the recipe is created.

### A compound variant

Each entry of `compoundVariants` is an object with these properties:

| Property    | Required | Description                                                                                                            |
| ----------- | -------- | ---------------------------------------------------------------------------------------------------------------------- |
| `variants`  | Required | The condition: for each variant it names, one option or a list of options. A variant it leaves out matches any option. |
| `className` | Required | The classes added when the condition matches.                                                                          |

```ts
{ variants: { tone: "danger", size: ["md", "lg"] }, className: "font-semibold" }
```

See [Compound variants](/recipe/class-recipe/variants/#compound-variants).

## The call

A recipe takes one optional argument, an object with these properties:

| Property              | Description                                                                                  |
| --------------------- | -------------------------------------------------------------------------------------------- |
| Each variant, by name | The option to use. Required for a variant without a default, unless it is a boolean variant. |
| `className`           | Optional. Classes added after every class of the recipe. It takes one string.                |

The recipe ignores every other property, so a component can pass it all
of its props. When every variant is optional, the argument is optional
too.

## The result

A recipe returns the class name as a string. It adds the classes in this
order:

1. `base`.
2. The classes of each variant's option, in the order of `variants`.
3. The classes of each matching compound variant, in the order of
   `compoundVariants`.
4. `className`.

The recipe builds the class name of each selection once and caches it, so
a later call with the same variants is a lookup. See
[How it works](/recipe/class-recipe/how-it-works/).

## Overriding classes

`className` adds classes after every class of the recipe:

<RecipeExample
  name="class-recipe/cva/badge"
  source={false}
  calls={[{ tone: "danger", outlined: true, className: "uppercase" }]}
/>

With the default join, these classes are added, not substituted. A class
that sets the same CSS property as a class of the recipe leaves both in
the class name. Design the recipe so that it needs no override (see
[Writing conflict-free recipes](/recipe/class-recipe/conflict-free-recipes/)),
or use a join such as `twMerge` (see
[Merging classes](/recipe/class-recipe/tailwind-merge/)).

## Listing the variants

| Property          | Type                                    | Description                                                     |
| ----------------- | --------------------------------------- | --------------------------------------------------------------- |
| `variantKeys`     | A readonly array of variant names       | The names of the variants, in the order of `variants`.          |
| `variantOptions`  | An object of readonly arrays of strings | For each variant, the names of its options.                     |
| `defaultVariants` | An object of strings                    | For each variant that may be left out, the option it uses then. |
