## As one config

A recipe that composes others behaves as if their configs and its own
were written as one config, theirs first:

| Property           | How the configs merge                                                                                                |
| ------------------ | -------------------------------------------------------------------------------------------------------------------- |
| `base`             | The base of each config, in order.                                                                                   |
| `variants`         | Every variant and option of each config is declared. An option that several configs give has their values, in order. |
| `compoundVariants` | The compound variants of each config, in order.                                                                      |
| `defaultVariants`  | The default of a variant is the last one given.                                                                      |
| `cache`            | The recipe's own, or its kind's.                                                                                     |

Where one config has one value, the merged config can have several: the
bases of several configs, or their values for one option. The kind adds
each in order, or combines them into one first, when it has
[`combine`](/recipe/recipe/recipe-kinds/#combine). Either way, a result is
what reducing them in order gives (see
[Combining values](#combining-values)).

The order of the values stays the one of a recipe: the bases, then the
value of each variant's option, then the matching compound variants (see
[How it works](/recipe/recipe/how-it-works/#the-order-of-the-values)).
Within a variant, the values of the recipes it composes come before its
own. Here is each call of the kind while `button` builds a result, with
the value it adds and the accumulator after it:

<RecipeTrace
  name="recipe/composing/button"
  recipe="button"
  call={{ size: "md", disabled: true }}
/>

The bases of `control` and `button` come first. `size: "md"` has a value in
both configs, and the value of `control` comes first. Both apply where
`size` does, before `disabled`, a variant of `control`. The compound
variant of `button` applies after every option, as it would in one config:
a compound variant can name the variants of the recipes it composes.

A recipe's own variant does not override a compound variant of a recipe it
composes, since compound variants apply last. To override one, give the
recipe a compound variant with the same condition, which applies after it.

A recipe reads the configs it composes when it is created. Changing a
config later changes neither its recipe nor the recipes that compose it.

## Several recipes

`composes` lists any number of recipes, in the order their configs merge.
A recipe that composes others can itself be composed, and its configs
come with it. A recipe that the list reaches more than once, directly or
through another recipe, counts once, where it first appears:

```ts
const iconButton = styleRecipe({
  composes: [button, control],
  variants: { shape: { square: { width: 40 } } },
});
// Merges control, then button, then iconButton: control counts once.
```

## Boolean variants

A variant whose only options, in every config, are `"true"` and `"false"`
is a boolean variant, optional and `false` by default. A recipe that adds
another option to it makes it an ordinary variant, which is required
unless a config gives it a default.

## Kinds

A recipe composes recipes of any kind whose values have the type of its
own kind's values: it merges their configs, and builds every result with
its own kind. A recipe that joins class names with `twMerge` can compose
one that concatenates them, for example.

A recipe composes only recipes that the engine created, and a slot recipe
only slot recipes. Anything else in `composes` is a type error, and throws
a `TypeError` when the recipe is created. This happens too when an app
installs two copies of `@lynstack/recipe`, since each copy knows only its
own recipes.

## Combining values

A recipe merges the configs it composes once, when it is created, and
compiles the result as it would compile one config. A cached call of a
composed recipe costs what a cached call of that one config costs (see
[Caching](/recipe/recipe/caching/#a-cached-call)).

Where one config has one value, the merged config can have several. Here
`button` composes `control`, and both have a base and give values to the
options of `size`:

<RecipeExample name="recipe/composing/composed-button" />

The merged config has two bases, and two values for each option of
`size`. Without the kind's
[`combine`](/recipe/recipe/recipe-kinds/#combine), the first base is passed
to `initial`, and the kind reduces every other base and value on each
call that builds a result:

<RecipeTrace
  name="recipe/composing/composed-button"
  recipe="button"
  call={{ size: "sm" }}
  title="Without combine"
/>

With `combine`, here `(first, second) => ({ ...first, ...second })`, the
recipe combines them into one when it is created, and builds results as
the one config they stand for would:

<RecipeTrace
  name="recipe/composing/composed-button"
  recipe="button"
  call={{ size: "sm" }}
  combine
  title="With combine"
/>

Both return the same result, which is what the
[rules of `combine`](/recipe/recipe/recipe-kinds/#combine) guarantee. With
`combine`, a result costs what a result of one config costs. Without it,
the kind reduces each base after the first, and each value of an option
that several configs give values to. A recipe whose configs give at most
one base, and never two values to one option, costs nothing more either
way.

## Types

A recipe that composes others infers its selection from every config:

- It accepts the options of each config for each variant.
- A variant is optional when any config gives it a default, or when it is
  a boolean variant.
- Its compound variants and default variants can name the variants and
  options of the recipes it composes.

```ts
import type { VariantsOf } from "@lynstack/recipe";

type ButtonVariants = VariantsOf<typeof button>;
// => { readonly size?: "sm" | "md" | "lg" | undefined;
//      readonly disabled?: boolean | "true" | "false" | undefined;
//      readonly tone?: "primary" | "neutral" | undefined }
```

`composes` takes the recipes as a list, inferred as a tuple, and each
recipe's type carries what it passes on to the recipes that compose it,
under a `~composition` property that exists in the type only. A library
that wraps recipes passes it on, as
[Making library recipes composable](/recipe/recipe/composable-libraries/)
shows.
