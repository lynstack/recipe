A recipe does its work in two phases: once when it is created, and on each
call. The kind takes part only when a result is built (see
[How the engine calls a kind](/recipe/recipe/recipe-kinds/#how-the-engine-calls-a-kind)).
This page follows one recipe through both, with the style kind of the
[Quick start](/recipe/recipe/quick-start/):

## When a recipe is created

The function that `createRecipeKind` returns compiles the config into a
recipe, once. A recipe that composes others first merges their configs
with its own into one (see [Recipes that compose others](#recipes-that-compose-others)),
and compiles that:

1. It numbers the options of each variant from 1. A variant that declares
   an option named `"true"` or `"false"` also declares the other one,
   without a value. The numbers follow the order of `Object.keys`:
   - first, the options whose names are integers, in ascending order;
   - then `"false"` and `"true"`, when the variant has them;
   - then the other options, in the order they are declared.
2. It sets the default of each variant: the option in `defaultVariants`, or
   `"false"` for a boolean variant, whose only options are `"true"` and
   `"false"`.
3. It turns each compound variant into the option numbers it matches,
   leaving out the options that a variant does not declare. A compound
   variant that names an undeclared variant, or is left without an option
   for a variant, can never match, and is dropped. Creating the recipe
   warns about each undeclared name (see
   [Names that a config does not declare](/recipe/recipe/api/#names-that-a-config-does-not-declare)).
4. It keeps the value of each option and compound variant, by reference.
   A recipe that composes others may combine several values into one
   first (see
   [Combining values](/recipe/recipe/composing/#combining-values)).

`disabled` declares only `true`, so the recipe adds `false`, without a
value, as its default. The place value of each variant is what its option
number counts for in a key, as the next section shows.

The recipe reads the config's objects of variants and options only here,
so changing them later does not change the recipe. It keeps the values
themselves, so treat them as immutable.

## When a recipe is called

1. **Select.** For each variant, the recipe takes the option the selection
   names, or the variant's default when the selection leaves it out or
   passes `undefined`. Numbers and booleans name the option of the same
   string. A selection of `undefined` or `null` is an empty one, and
   properties that are not variants are ignored.
2. **Key.** Each option number, times the place value of its variant,
   adds up to the selection's key. The option numbers are the digits of
   one number, so every declared selection has its own integer.
3. **Look up.** If the recipe has built the result of this key before, it
   returns that result. A cached call stops here; see
   [A cached call](/recipe/recipe/caching/#a-cached-call) for its cost. A
   call that finds no result goes on to the next two steps.
4. **Build.** The kind builds the result: `initial` returns the
   accumulator for the recipe's base, `reduce` adds each value that applies
   to the selection, and `finish` turns the accumulator into the result.
5. **Store.** The recipe caches the result under the key and returns it.

A selection with an option that its variant does not declare has no key:
it is built on every call, and that option adds no value. See
[Caching](/recipe/recipe/caching/) for when a recipe caches.

## The order of the values

`reduce` receives the values that apply to a selection in a fixed order,
from the least to the most specific:

1. The value of each variant's selected option, in the order of
   `variants`.
2. The value of each compound variant that matches, in the order of
   `compoundVariants`.

The base is not reduced: it is passed to `initial`. A value that is
`undefined` is skipped, so an option without a value adds nothing. Here is

order.

## Recipes that compose others

A recipe that composes others merges their configs with its own into one,
when it is created, and compiles that one config as above. See
[Composing recipes](/recipe/recipe/composing/#combining-values), which
traces a recipe built with and without the kind's `combine`.

## Slot recipes

A slot recipe selects, keys, and caches in the same way, and builds the
result of each slot as a recipe would, from that slot's values only. See
[Slot recipes](/recipe/recipe/slot-recipes/).
