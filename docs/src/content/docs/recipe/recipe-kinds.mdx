A **kind** is how a recipe turns the values of a selection into its
result. It is the only part of a recipe that you write; the engine does
the rest. `createRecipeKind` and `createSlotRecipeKind` take the same kind:

```ts
interface RecipeKind<Value, Accumulator, Result> {
  readonly initial: (base: Value | undefined) => Accumulator;
  readonly reduce: (accumulator: Accumulator, value: Value) => Accumulator;
  readonly combine?: ((first: Value, second: Value) => Value) | undefined;
  readonly finish?: ((accumulator: Accumulator) => Result) | undefined;
  readonly cache?: boolean | undefined;
}
```

- **`Value`** is what a config gives: the base, the value of each option,
  and the value of each compound variant.
- **`Accumulator`** is what the values are reduced into while a result is
  built.
- **`Result`** is what a recipe returns. Without `finish`, it is the
  accumulator.

A result is built in three steps: `initial` starts an accumulator from the
recipe's base, `reduce` adds each value that applies to the selection, and
`finish` turns the accumulator into the result.

## `initial`

```ts
readonly initial: (base: Value | undefined) => Accumulator;
```

Returns the accumulator a result starts from, given the recipe's `base`,
or `undefined` when the recipe has none.

- It is called once for each result a recipe builds, and once for each
  slot of each result a slot recipe builds.
- It may return a new object each time, which `reduce` can then change in
  place.
- It must not change `base`, which every result shares.

## `reduce`

```ts
readonly reduce: (accumulator: Accumulator, value: Value) => Accumulator;
```

Adds one value to the accumulator and returns the accumulator: the same
one, changed, or a new one.

- It is called with each value that applies to the selection, from the
  least to the most specific: the value of each variant's selected option,
  in the order of `variants`, then the value of each matching compound
  variant, in the order of `compoundVariants` (see
  [The order of the values](/recipe/recipe/how-it-works/#the-order-of-the-values)).
- It is never called with `undefined`: an option without a value adds
  nothing.
- It may be called no times at all, when no option or compound variant
  adds a value.
- It must not change `value`, which every result shares.

## `combine`

```ts
readonly combine?: ((first: Value, second: Value) => Value) | undefined;
```

Returns one value that adds what `first` then `second` add. Only a recipe
that [composes](/recipe/recipe/composing/) others calls it, when it is
created: it combines the bases of its configs, and the values that its
configs give one option, so that it reduces one value for each, as the one
config it stands for would. A slot recipe combines the values of each slot
in the same way.

- It must not change `first` or `second`, which other recipes share.
- Without it, a composed recipe reduces each value, which gives the same
  results, at a cost (see
  [Composing recipes](/recipe/recipe/composing/#combining-values)).

A kind with `combine` follows two more rules. In each, the two
accumulators must be interchangeable: `finish` returns the same result for
both, and again after the same values are reduced into each.

- **Combining is reducing.** Reducing `first` then `second` into an
  accumulator gives what reducing `combine(first, second)` gives.
- **A base is the first value.** `initial(base)` gives what reducing
  `base` into `initial(undefined)` gives.

In familiar terms, `combine` is to values what concatenation is to lists:
reducing two values joined by `combine` is reducing each in turn.
`undefined` means "no value", so `initial(undefined)` is the empty
accumulator, and a base is reduced into it like any other value.

For class names, `combine` joins two strings of classes with a space, and
for styles, it spreads both into a new object. A kind that cannot turn two
values into one, such as one that counts its values, leaves it out.

## `finish`

```ts
readonly finish?: ((accumulator: Accumulator) => Result) | undefined;
```

Turns the accumulator into the result, once for each result built. Use it
to freeze the result, to convert the accumulator into another type, or to
do work that needs every value at once, such as resolving conflicts
between them. Without it, the result is the accumulator.

## `cache`

```ts
readonly cache?: boolean | undefined;
```

Whether a recipe builds the result of each declared selection once and
returns it again for the same selection. It defaults to `true`, and the
`cache` of a recipe's config overrides it. See
[Caching](/recipe/recipe/caching/).

## How the engine calls a kind

The engine calls a kind's functions at fixed times, and in a fixed way:

- **As plain functions.** The engine reads `initial`, `reduce`, `combine`,
  and `finish` from the kind when it creates each recipe, and calls them
  apart from the kind object, as `const { initial, reduce, finish } = kind`
  would. `this` is `undefined` in them, so a kind written as a class whose
  methods read `this` throws. Write plain functions that close over what
  they need.
- **`cache`, once.** `createRecipeKind` and `createSlotRecipeKind` read
  `cache` once, when they are called. Changing it later changes nothing.
- **`combine`, when a recipe is created.** A recipe that composes others
  combines the values of each base and option then, as a left fold:
  `combine(combine(a, b), c)` for three values. It never calls `combine`
  for a single value, so a recipe that composes nothing never calls it.
- **`initial`, `reduce`, and `finish`, only to build a result.** None runs
  when a recipe is created. With the cache, they run on the first call of
  each selection; without it, on every call.
- **When a function throws,** the call throws, and nothing is cached. The
  next call with the same selection builds the result again.
- **An `undefined` result is cached** like any other result.
- **Never call a recipe from inside its own kind.** A recipe keeps the
  options of the selection it is building in state that all of its calls
  share. A kind that calls the same recipe while it builds a result
  changes that state, and the outer result is built from the wrong
  options. Calling another recipe is safe.

## The rules of a kind

- **Be pure.** With the cache, a result is built once and returned to
  every later call with the same variants, so a kind that reads anything
  besides its arguments, such as the current theme, returns what it read
  the first time.
- **Never change what you receive from the config.** The base and the
  values are shared by every result. Change only the accumulator that
  `initial` returned for this result.
- **Never share a result that can change.** A cached result is shared by
  every call with the same variants; freeze an object result in `finish`.
- **Combine as you reduce.** A `combine` that gives another result than
  reducing each value changes what composed recipes return. See
  [`combine`](#combine).

## Types

A kind's types are inferred from its functions:

- `Value` comes from the `value` parameter of `reduce` or the `base`
  parameter of `initial`, so annotate one of them. Without either, values
  are `unknown` and a config accepts anything.
- `Accumulator` comes from the return type of `initial`.
- `Result` comes from the return type of `finish`.

Every recipe of the kind then checks its config against `Value`: a base,
option, or compound value of another type is a type error.

Style objects, copied once and frozen, as in the
[Quick start](/recipe/recipe/quick-start/):

```ts
type Style = Readonly<Record<string, string | number>>;
type MutableStyle = Record<string, string | number>;

const styleRecipe = createRecipeKind({
  initial: (base?: Style): MutableStyle => ({ ...base }),
  reduce: (style: MutableStyle, value: Style) => Object.assign(style, value),
  combine: (first: Style, second: Style): Style => ({ ...first, ...second }),
  finish: (style: MutableStyle): Style => Object.freeze(style),
});
```
