`@lynstack/native-recipe` maps a component's props to its React Native
styles. You write the styles of each prop value once, in a
[recipe](/recipe/native-recipe/glossary/#recipe), and call it with the
props to get the style.

<RecipePlayground name="native-recipe/index/badge" />

```ts
badge({ tone: "danger" }) === badge({ tone: "danger" }); // => true
```

<Aside title="Words used here">
  A **[variant](/recipe/native-recipe/glossary/#variant)** is a prop that
  changes the style, such as `tone`. An
  **[option](/recipe/native-recipe/glossary/#option)** is one of its values,
  such as `"danger"`. A **[slot](/recipe/native-recipe/glossary/#slot)** is one
  element of a component. The [glossary](/recipe/native-recipe/glossary/)
  defines every term.
</Aside>

## Which function to use

| You want to style                                | Use                                                                                                |
| ------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| One element, such as a badge                     | [`createStyleRecipe`](/recipe/native-recipe/create-style-recipe/)                                  |
| Several elements, such as a button and its label | [`createSlotStyleRecipe`](/recipe/native-recipe/create-slot-style-recipe/)                         |
| Elements whose styles come from theme tokens     | [`createThemedRecipes`](/recipe/native-recipe/create-themed-recipes/), which returns both creators |

## What it gives you

- **Stable styles.** A recipe builds the style of each selection once and
  returns the same frozen object for it. The `style` prop keeps its
  identity between renders, so React skips comparing it and a memoized
  child skips rendering (see
  [How it works](/recipe/native-recipe/how-it-works/)).
- **Type-safe.** Every style is checked against the styles of React
  Native, as in `StyleSheet.create`. The result keeps the types of the
  properties the config declares, so a text style passed to a `View` is a
  type error. Variant names, options, and slots are inferred from the
  config, and a variant without a default is required.
- **Themes.** Build styles from the tokens of a design system, and switch
  between light and dark, or any theme, without writing each theme's
  styles in every recipe (see
  [Theming with design tokens](/recipe/native-recipe/themes/)).
- **Fast.** A call with the cache is a lookup, about {styleRecipeSpeedup}
  times as fast as merging the styles again (see
  [Benchmarks](/recipe/native-recipe/performance/)).
- **Small.** ES modules only, with no code from React Native at runtime.
  It needs no provider, Babel plugin, or native module.

## When to use it

Use it to style React Native components whose styles depend on their
props, their state, or a theme. Keep styles that never change in
`StyleSheet.create` (see
[Why native-recipe](/recipe/native-recipe/why-native-recipe/)). To style
components on the web with class names, use
[`@lynstack/class-recipe`](/recipe/class-recipe/).
