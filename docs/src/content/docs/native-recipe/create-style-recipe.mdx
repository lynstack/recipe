`createStyleRecipe` creates a style recipe, which returns the style of one
element for a selection of variants.

<RecipePlayground name="native-recipe/create-style-recipe/badge" />

Pass the result to the `style` prop of the element: `<View
style={badge({ tone })} />`. For what variants, options, and compound
variants are, see [Variants](/recipe/native-recipe/variants/).

## Signature

```ts
// Simplified: the type parameters are left out.
function createStyleRecipe(config: StyleRecipeConfig): StyleRecipe;
```

TypeScript infers the variants, options, and style types from `config`,
so you never write type arguments. The full types are on
[All exports](/recipe/native-recipe/exports/).

## The config

| Property           | Required | Description                                                                                                                            |
| ------------------ | -------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `variants`         | Required | For each variant name, the style of each of its options. Write `variants: {}` when the recipe has none.                                |
| `base`             | Optional | The style the element always has.                                                                                                      |
| `compoundVariants` | Optional | Styles added when several variants have particular options at the same time, in order. See [Compound variants](#compound-variants).    |
| `defaultVariants`  | Optional | The option each variant uses when a call leaves it out. A variant without a default is required.                                       |
| `composes`         | Optional | Style recipes whose configs the recipe adds before its own. See [Composing recipes](#composing-recipes).                               |
| `cache`            | Optional | Whether the recipe caches its styles. Defaults to `true`. With `false`, every call returns a new object, so leave it on in components. |

`variants` is required even when it is empty. Without it, TypeScript
reports `Property 'variants' is missing` (TS2741):

```ts
// Error: Property 'variants' is missing.
createStyleRecipe({ base: { padding: 8 } });

createStyleRecipe({ base: { padding: 8 }, variants: {} });
```

In JavaScript, or in a config that bypasses the types, creating the
recipe throws a `TypeError` that names what is wrong: no `variants`, a
style that is not an object, or a compound variant without `variants` or
`style`.

A style that never changes does not need a recipe, though: keep it in
`StyleSheet.create` (see
[Building components](/recipe/native-recipe/building-components/#keep-static-styles-in-stylesheetcreate)).

Every style is checked against the styles of React Native, as in
`StyleSheet.create` (see
[Typing recipes](/recipe/native-recipe/typescript/)).

## Compound variants

Each item of `compoundVariants` is an object of type
`StyleCompoundVariant`:

| Property   | Required | Description                                                                                                      |
| ---------- | -------- | ---------------------------------------------------------------------------------------------------------------- |
| `variants` | Required | The condition: one option, or a list of options, for each variant it names. A variant it leaves out matches any. |
| `style`    | Required | The style added when the condition matches.                                                                      |

```ts
compoundVariants: [
  { variants: { tone: "danger", size: ["sm", "md"] }, style: { borderWidth: 2 } },
],
```

The condition is checked after defaults apply. A compound variant that
names an undeclared variant, or lists no declared option for a variant,
never matches.

## The result

A recipe is a function. It takes a selection and returns a style:

- **Frozen.** The style is a frozen object. Do not change it or spread
  it.
- **The same object for the same variants.** The recipe builds the style
  of each selection once. Every later call with the same variants,
  including variants left to their defaults, returns that same object.
  So the `style` prop keeps its identity between renders (see
  [How it works](/recipe/native-recipe/how-it-works/#stable-styles)).
- **In a fixed order.** The style merges `base`, then the style of each
  variant's option, in the order of `variants`, then each matching
  compound variant, in the order of `compoundVariants`. A later style
  overrides the properties of an earlier one, as `StyleSheet.flatten`
  does. A property set to `undefined` is copied too, so it overrides an
  earlier value.

The argument is optional when every variant is optional. A call with no
argument, `undefined`, or `null` is the same as a call with `{}`. Props
that are not variants are ignored (see
[Variants](/recipe/native-recipe/variants/#details)).

Create each recipe once, at the top level of a module, not inside a
component, so that its cache lasts.

## Listing the variants

A recipe has three frozen properties that list its variants. They are
typed with the names of its variants and options.

| Property          | Description                                                                                                                                                                                                |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `variantKeys`     | The names of the variants, in the order of `variants`.                                                                                                                                                     |
| `variantOptions`  | The options of each variant, as strings. The order: integer names first, from smallest to largest; then `"false"` and `"true"` for a boolean variant; then the other names, in the order you declare them. |
| `defaultVariants` | The option, as a string, that each optional variant uses when a call leaves it out: its default, or `"false"` for a boolean variant.                                                                       |

Use `variantKeys` to split a component's props (see
[Building components](/recipe/native-recipe/building-components/#split-props-with-variantkeys)),
and `variantOptions` to show every look of a component.

## Composing recipes

`composes` lists style recipes whose configs the recipe adds before its
own. The recipe accepts their variants too. See
[Composing recipes](/recipe/native-recipe/composing/).

## Overriding styles

You cannot pass extra styles into a recipe call. Merge them in the
`style` prop instead (see
[Building components](/recipe/native-recipe/building-components/#overriding-styles)).
