This page styles a badge, a button, and a card. Install the package first
(see [Installation](/recipe/native-recipe/installation/)).

## 1. Create a recipe

A [recipe](/recipe/native-recipe/glossary/#recipe) is a function made from
your style config. `createStyleRecipe` takes the styles of one element:

- `base`: the style it always has.
- `variants`: for each [variant](/recipe/native-recipe/glossary/#variant),
  a prop such as `tone`, the style of each
  [option](/recipe/native-recipe/glossary/#option), a value such as
  `"success"`.
- `compoundVariants`: styles for combinations of options.
- `defaultVariants`: the option each variant uses when you leave it out.

Create it once, at the top level of a module, as you would call
`StyleSheet.create`:

<RecipeExample name="native-recipe/quick-start/badge" />

## 2. Call it

Call the recipe with a
[selection](/recipe/native-recipe/glossary/#selection), the variants you
choose. It returns the style:

<RecipeExample
  name="native-recipe/quick-start/badge"
  source={false}
  calls={[
    {},
    { tone: "success", size: "sm" },
    { tone: "danger", outlined: true },
  ]}
/>

- `tone` and `size` have defaults, so you can leave them out.
- `outlined` has only a `true` option. That makes it a
  [boolean variant](/recipe/native-recipe/glossary/#boolean-variant). You
  can leave it out, and then it is `false`.
- The compound variant adds its style when `tone` is `danger` and
  `outlined` is `true`. It applies after the styles of the variants, so
  its border color wins.

Calling it again with the same variants returns the same frozen object:

## 3. Use it in a component

`VariantsOf` types a component's props from its recipe. Pass the style to
the `style` prop:

```tsx
import type { ReactNode } from "react";
import type { VariantsOf } from "@lynstack/native-recipe";
import { View } from "react-native";

type BadgeProps = VariantsOf<typeof badge> & { children: ReactNode };

export function Badge({ children, ...variants }: BadgeProps) {
  return <View style={badge(variants)}>{children}</View>;
}
```

A recipe reads only its variants, so it can take every prop of the
component at once. See
[Building components](/recipe/native-recipe/building-components/) for
style overrides and memoized components.

## 4. Style several elements with a slot recipe

React Native styles do not cascade, so a component of several elements,
such as a button and its label, needs a style for each. A
[slot recipe](/recipe/native-recipe/glossary/#slot-recipe) returns one
style for each element, its [slots](/recipe/native-recipe/glossary/#slot):

<RecipeExample
  name="native-recipe/quick-start/button"
  calls={[{ size: "sm" }]}
/>

```tsx
import type { VariantsOf } from "@lynstack/native-recipe";
import { Pressable, Text } from "react-native";

type ButtonProps = VariantsOf<typeof button> & {
  title: string;
  onPress: () => void;
};

export function Button({ title, onPress, ...variants }: ButtonProps) {
  const styles = button(variants);
  return (
    <Pressable style={styles.root} onPress={onPress}>
      <Text style={styles.label}>{title}</Text>
    </Pressable>
  );
}
```

The slot names are your own. `root` and `label` are only names: name the
slots after the parts of your component. A card can have a `container`, a
`title`, and a `body`:

<RecipeExample
  name="native-recipe/quick-start/card"
  calls={[{ tone: "inverted" }]}
/>

```tsx
import type { ReactNode } from "react";
import type { VariantsOf } from "@lynstack/native-recipe";
import { Text, View } from "react-native";

type CardProps = VariantsOf<typeof card> & {
  title: string;
  children: ReactNode;
};

export function Card({ title, children, ...variants }: CardProps) {
  const styles = card(variants);
  return (
    <View style={styles.container}>
      <Text style={styles.title}>{title}</Text>
      <Text style={styles.body}>{children}</Text>
    </View>
  );
}
```

See [createSlotStyleRecipe](/recipe/native-recipe/create-slot-style-recipe/).

## 5. Build styles from a theme

The colors above are written in each recipe. A design system keeps them
in a [theme](/recipe/native-recipe/glossary/#theme) instead, with one
theme for light and one for dark. `createThemedRecipes` returns recipe
creators whose config is a function of the theme. Their recipes take the
theme first, then the variants:

```ts
import { createThemedRecipes } from "@lynstack/native-recipe";

interface Theme {
  readonly colors: { readonly primary: string; readonly onPrimary: string };
  readonly radius: { readonly md: number };
}

const { createSlotStyleRecipe } = createThemedRecipes<Theme>();

export const themedButton = createSlotStyleRecipe((theme: Theme) => ({
  slots: ["root", "label"],
  base: {
    root: {
      borderRadius: theme.radius.md,
      backgroundColor: theme.colors.primary,
    },
    label: { color: theme.colors.onPrimary },
  },
  // Required, even when a recipe has no variants: then write `variants: {}`.
  variants: {
    size: {
      sm: { root: { height: 32 }, label: { fontSize: 14 } },
      md: { root: { height: 40 }, label: { fontSize: 16 } },
    },
  },
  defaultVariants: { size: "md" },
}));

const light: Theme = {
  colors: { primary: "#2563eb", onPrimary: "#ffffff" },
  radius: { md: 8 },
};

// The theme first, then the variants.
const styles = themedButton(light, { size: "sm" });
styles.root; // borderRadius 8, the light primary color, and height 32
```
