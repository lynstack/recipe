`createThemedRecipes` returns `createStyleRecipe` and
`createSlotStyleRecipe` for a theme type, and `themeToken`, the theme
whose recipe is being built. Each creator takes a function that returns
the config of the recipe, which reads the tokens from `themeToken`. Each
returns a themed recipe, which takes the theme first, then the
selection.

<RecipeExample name="native-recipe/create-themed-recipes/button" />

`button(light, { tone: "surface" })` returns the style of the light
theme, and `button(dark, { tone: "surface" })` the style of the dark one.
They are the styles that the recipe of each theme returns, which
[`withTheme`](#withtheme) gives:

Call `createThemedRecipes` once, in a module of your own, and import its
recipe creators and `themeToken` wherever you create recipes (see
[Theming with design tokens](/recipe/native-recipe/themes/#2-create-the-recipe-creators)).
Every recipe they create takes the theme type that you give it.

## Signature

```ts
// Simplified: the type parameters of each creator are left out.
function createThemedRecipes<Theme extends object>(): {
  readonly themeToken: Theme;
  createStyleRecipe(
    config: (theme: Theme) => StyleRecipeConfig,
  ): ThemedRecipe<Theme>;
  createSlotStyleRecipe(
    config: (theme: Theme) => SlotStyleRecipeConfig,
  ): ThemedRecipe<Theme>;
};
```

`Theme` is the type of your theme objects. `themeToken` reads the theme
whose recipe is being built, while its config function runs. The return
type is `ThemedRecipeCreators<Theme>`.

## The config function

The function reads the theme from `themeToken` and returns the config of a
[style recipe](/recipe/native-recipe/create-style-recipe/#the-config) or
of a [slot style recipe](/recipe/native-recipe/create-slot-style-recipe/#the-config).
It has the same properties and the same checks, `variants` included.
TypeScript infers the variants, options, and slots from what it returns.
A token is typed as the theme type declares it.

The function runs once for each theme object, and `themeToken` reads that
theme while it runs. So a token can be computed, as in
`themeToken.gap * 2`, or branched on. Read `themeToken` only inside the
function: read anywhere else, such as in
`const { colors } = themeToken` at the top level of a module, it throws a
`TypeError`.

Every theme must give the same variants, options, and slots. Only the
styles may change with the theme. So when you branch on a token, branch
inside a style. Never add or remove a variant or an option for one
theme. For a theme with a `highContrast` flag:

```ts
// Right: the branch is inside the style.
createStyleRecipe(() => ({
  variants: {
    outlined: { true: { borderWidth: themeToken.highContrast ? 2 : 1 } },
  },
}));

// Wrong: the branch is around the variant, so one theme has no `outlined`.
// TypeScript reports an error here. With exactOptionalPropertyTypes, it
// reports one at each call that sets `outlined` instead.
const box = createStyleRecipe(() => ({
  variants: themeToken.highContrast
    ? {}
    : { outlined: { true: { borderWidth: 1 } } },
}));

box(light, { outlined: true });
```

### Editor completions

Write the function in the call, as `() => ({ … })`, and read the tokens
from `themeToken`. TypeScript infers the variants, options, and slots of
the config from what the function returns. While the config has an error,
as it often has while you write it, your editor still completes the names
of the variants, options, and slots, and TypeScript reports each error
where it is, with a short message:

```ts
createSlotStyleRecipe(() => ({
  slots: ["root"],
  variants: { raised: { true: { root: { elevation: 2 } } } },
  // Completes `raised` after `r`.
  compoundVariants: [{ variants: { r }, styles: {} }],
}));
```

The function can also take the theme as a parameter, as in
`(theme: Theme) => ({ … })`. Your editor completes the config as well,
but TypeScript reports any error in the config on the whole function,
with a long message, since it does not follow an error into a function
whose parameters have types. Without the type, as in `(theme) =>`, your
editor completes nothing while the config has an error.

A config declared before the call takes the theme as its typed parameter,
since `ThemedStyleRecipeOf` and `ThemedSlotStyleRecipeOf` read the theme
type from it (see
[Exporting recipes](/recipe/native-recipe/exporting-recipes/#themed-recipes)).
Either way, the recipe and its checks are the same.

## Calling a themed recipe

A themed recipe takes the theme, then the selection. The selection is
optional when every variant is optional:

<EvaluatedCode name="native-recipe/create-themed-recipes/call" />

It returns the same frozen style for the same theme object and the same
variants.

## Theme identity

A themed recipe keeps one recipe, with its own cache, for each theme
object:

- The first call with a theme object builds the config for that theme,
  and creates a recipe from it. Later calls with the same object reuse
  that recipe and its cache.
- Each theme has its own cache. Switching to another theme and back
  returns the cached styles of the first theme.
- A new object is a new theme, even with the same tokens. It builds a new
  recipe with an empty cache. So create each theme once, at the top level
  of a module, or memoize a theme that you build at runtime (see
  [Keep each theme stable](/recipe/native-recipe/themes/#keep-each-theme-stable)).
- A theme object that nothing references anymore is released, with its
  recipe.

## `withTheme`

`withTheme(theme)` returns the recipe of one theme. It is a plain recipe:
it takes only a selection, and it has `variantKeys`, `variantOptions`, and
`defaultVariants`. It returns the same recipe for the same theme object.

<EvaluatedCode name="native-recipe/create-themed-recipes/with-theme" />

Use it to:

- Read the lists of the variants. A themed recipe has no `variantKeys` of
  its own, since it needs a theme to build its config.
- Pass a recipe to code that takes a plain recipe, such as a child
  component that does not know about themes.
- Compose a themed recipe in another one (see below).

## Composing themed recipes

To compose a themed recipe, list `withTheme(themeToken)` in `composes`.
It returns the recipe of the theme being built, so each theme composes
the recipe of the same theme:

```ts
const iconButton = createStyleRecipe(() => ({
  composes: [button.withTheme(themeToken)],
  base: { width: 40, height: 40 },
  variants: {},
}));
```

A themed recipe can also compose recipes without a theme. A themed slot
recipe composes the `withTheme(themeToken)` of another themed slot recipe in
the same way. See
[Composing recipes](/recipe/native-recipe/composing/#compose-themed-recipes)
for an example with its output.

## Slot recipes

`createSlotStyleRecipe` works the same way for slot recipes:

```ts
const { createSlotStyleRecipe, themeToken } = createThemedRecipes<Theme>();

const card = createSlotStyleRecipe(() => ({
  slots: ["root", "title"],
  base: {
    root: { borderRadius: themeToken.radius },
    title: { fontSize: 16 },
  },
  variants: {
    raised: {
      true: { root: { backgroundColor: themeToken.colors.surface } },
    },
  },
}));

card(dark, { raised: true }).root; // the root style of the dark theme
```

## Types

`VariantsOf` returns the variants of a themed recipe, as of any recipe:

```ts
import type { VariantsOf } from "@lynstack/native-recipe";

type ButtonVariants = VariantsOf<typeof button>;
// => { readonly tone?: "primary" | "surface" | undefined }
```

`ThemedRecipe` is the type of a themed recipe, and `ThemedRecipeCreators`
the type of what `createThemedRecipes` returns (see
[All exports](/recipe/native-recipe/exports/)).
