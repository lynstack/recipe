`createSlotStyleRecipe` creates a slot style recipe, which returns the
style of each element of a component, its slots, for a selection of
variants. React Native styles do not cascade, so a component of several
elements, such as a button with a label, needs a style for each. The slot
names are your own: name them after the parts of your component.

<RecipePlayground name="native-recipe/create-slot-style-recipe/card" />

```tsx
<View style={styles.root}>
  <Text style={styles.title}>{title}</Text>
  <Text style={styles.body}>{children}</Text>
</View>
```

## Signature

```ts
// Simplified: the type parameters are left out.
function createSlotStyleRecipe(config: SlotStyleRecipeConfig): SlotStyleRecipe;
```

TypeScript infers the slots, variants, options, and style types from
`config`, so you never write type arguments.

## The config

The config is the config of a
[style recipe](/recipe/native-recipe/create-style-recipe/#the-config),
with `slots`. Wherever a style recipe takes a style, a slot recipe takes
an object of styles keyed by slot name.

| Property           | Required | Description                                                                                                                             |
| ------------------ | -------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `slots`            | Required | The names of the slots, in the order of the result.                                                                                     |
| `variants`         | Required | For each variant name, the styles of the slots for each option. Write `variants: {}` when the recipe has none.                          |
| `base`             | Optional | The style each slot always has.                                                                                                         |
| `compoundVariants` | Optional | Styles added to some slots when several variants have particular options at the same time. See [Compound variants](#compound-variants). |
| `defaultVariants`  | Optional | The option each variant uses when a call leaves it out. A variant without a default is required.                                        |
| `composes`         | Optional | Slot style recipes whose configs the recipe adds before its own. See [Composing slot recipes](#composing-slot-recipes).                 |
| `cache`            | Optional | Whether the recipe caches its styles. Defaults to `true`. With `false`, every call returns a new object, so leave it on in components.  |

An option or a compound variant gives styles only to the slots it names.
A style for a slot that `slots` does not declare is a type error. It is
ignored, and the recipe warns about it when it is created (see
[Names the config does not declare](/recipe/native-recipe/create-style-recipe/#names-the-config-does-not-declare)).
Variants, defaults, boolean variants, and undeclared options work as in a
style recipe (see [Variants](/recipe/native-recipe/variants/)).

A slot named after a property that every object has, such as `toString`
or `constructor`, is not supported: the types reject an object of slot
styles that leaves it out, since every object has that property with
another type.

## Compound variants

Each item of `compoundVariants` is an object of type
`SlotStyleCompoundVariant`. It uses `styles`, with a style for each slot,
where a style recipe uses `style`:

| Property   | Required | Description                                                                                                      |
| ---------- | -------- | ---------------------------------------------------------------------------------------------------------------- |
| `variants` | Required | The condition: one option, or a list of options, for each variant it names. A variant it leaves out matches any. |
| `styles`   | Required | The style to add to each slot it names when the condition matches.                                               |

## The result

A slot recipe returns an object with the style of each slot.

- **Frozen.** The object and the style of each slot are frozen.
- **The same object for the same variants.** The recipe builds the
  styles of each selection once, and returns the same object, with the
  same style for each slot, on every later call with the same variants.
- **In a fixed order.** Each slot's style merges its base style, then its
  style for each variant's option, then its style for each matching
  compound variant, as in a
  [style recipe](/recipe/native-recipe/create-style-recipe/#the-result).
- **Every slot.** Every slot is in the result. A slot that gets no style
  is an empty style, so its element can always receive it.

## Listing the variants

A slot recipe has the same `variantKeys`, `variantOptions`, and
`defaultVariants` as a style recipe (see
[createStyleRecipe](/recipe/native-recipe/create-style-recipe/#listing-the-variants)).

## Composing slot recipes

`composes` lists slot style recipes whose configs the slot recipe adds
before its own. The slot recipe has the slots of each, theirs first, and
can style any of them. See
[Composing recipes](/recipe/native-recipe/composing/#compose-slot-recipes).
